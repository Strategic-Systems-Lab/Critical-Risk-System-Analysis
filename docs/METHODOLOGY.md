# Methodology & Limitations

This document explains how RiskAI calculates its results, what assumptions those calculations rest on, and — just as importantly — what the platform does not and cannot do.

---

## Methodology

### Risk Scoring

Most risk categories (57 of 60, across all six domains) are calculated by a shared formula that compares a **"bad" factor** (inputs that increase risk) against a **"good" factor** (inputs that offset it), scaled by:

- a **sensitivity multiplier** specific to that category (how sharply it reacts to input changes)
- the **simulation horizon** (risk compounds slightly with more years)
- a **domain-specific floor and ceiling** (each category has a realistic minimum and maximum it can reach)

This default calculation is deterministic: identical inputs always produce identical outputs, with no randomness involved.

**Exception:** Company's "Financial" risk category does not use this shared formula. See [Data-Grounded Exceptions](#data-grounded-exceptions) below.

### Data-Grounded Exceptions

Three mechanisms deviate from the default heuristic formula above because real, citable data or peer-reviewed methodology was available and integrated directly:

- **Company / Financial risk** uses an adapted **Altman Z''-Score** (1995 revision, for private/non-manufacturing firms) — a peer-reviewed bankruptcy-prediction model published in 1968, with its original coefficients used unmodified. Two of its four required ratios are computed directly from user inputs (assets, debt, revenue, expenses, and cash reserves); one ratio (Retained Earnings) is still approximated via book equity, since RiskAI doesn't track accumulated historical earnings — an open, documented limitation.
- **Stocks/ETF and Retirement wealth projections** use a **500-path Monte Carlo simulation**, calibrated to long-run historical market statistics (broad equities ⌀10% annual return / ~19% volatility; a safe-asset blend ⌀4.5% / ~6%), rather than a single deterministic growth rate. This is the one place in RiskAI where genuine random sampling occurs — each of the 500 simulated paths draws a different randomized annual return. The randomness is seeded from the input parameters, so identical inputs still always reproduce identical output; the simulation is reproducible, not literally non-deterministic from the user's perspective.
- **Retirement / Longevity risk** uses a **period life-expectancy table** (a Western-Europe/Germany blended approximation of published actuarial data) instead of an arbitrary formula, to estimate how many years of retirement funding a person is likely to need.

Every other risk category — the remaining 57 — is a heuristic formula calibrated by domain reasoning, not fitted to historical outcome data. That remains true and is not expected to change wholesale; see [Assumptions](#assumptions) and [Future Improvements](#future-improvements).

### Stability Score

A single stability score per simulation is derived by aggregating a subset of "good" and "bad" factors relevant to that domain, weighted against a domain-specific baseline. The multi-year trajectory shown in the sparkline chart uses a deterministic curve toward that stability value — not a stochastic (random-walk) projection. This is unaffected by the Monte Carlo exception above, which applies only to wealth/cash projections, not to risk percentages or the stability score.

### Current Model Type

RiskAI's risk models are **rule-based**, not machine-learning-based, and remain so even where real external data is used: there is no training data, no learned parameters, and no model that updates itself over time. The Data-Grounded Exceptions above are fixed, published methodologies and historical statistics applied directly — not fitted or trained on RiskAI's own outcome data, because no such outcome data exists.

### AI-Style Reporting

The "Strategic Analysis Engine" report is generated by a template-driven text engine that reads the calculated risk values and assembles a structured narrative (situation assessment, root cause explanation, priority actions, trajectory forecast). It is not a live large language model call — the app is explicit about this in its own UI.

### Architecture for Future Models

Package 1 (the core simulation engine) and Package 2 (the Risk Intelligence layer) are deliberately decoupled: Package 2 only ever reads a finished simulation result and never touches Package 1's calculations. This means a future, more sophisticated risk model (see [Future Improvements](#future-improvements)) could replace or extend Package 1's formulas without requiring changes to Package 2, the UI, or the reporting layer. The three Data-Grounded Exceptions above were added under exactly this architecture, without any changes to Package 2.

## Explainability

RiskAI is built on the position that a risk score without a visible cause is close to useless for decision-making.

Every generated recommendation in Package 2's Mission Engine is tied back to the specific input parameter(s) that drive the underlying risk category — not a generic "improve this" statement. A user working on Retirement risk, for example, sees exactly which levers (`pension_assets`, `state_pension_reliance`) are responsible for a given score, rather than a category name alone.

This matters more than raw predictive accuracy for a tool positioned as decision support rather than a forecast: a user needs to know **why** a number moved and **what to change**, not just that it moved. Transparent, traceable formulas make that possible in a way opaque scoring cannot — and it applies equally to the Data-Grounded Exceptions: the Altman Z-Score and Monte Carlo engine are just as traceable to their inputs as every heuristic formula, unlike a black-box model would be.

## Assumptions

RiskAI's outputs rest on several explicit assumptions:

- **User input accuracy** – results are only as meaningful as the values a user provides; no input validation against external data sources occurs
- **Simplified models** – each domain uses a small number of representative risk factors (up to 10), not an exhaustive real-world risk taxonomy
- **Scenario-based estimation** – for the 57 heuristic categories, outputs represent a plausible trajectory given the stated inputs, not a statistical forecast with confidence intervals. The Monte Carlo wealth projections are the exception: they do produce a genuine probability range (10th–90th percentile), because that specific mechanism is built for it
- **Domain-specific calibration** – risk percentages are not directly comparable across domains (a 60% Cyber risk for a Company and a 60% Vacancy risk for Real Estate are calibrated independently, not on a shared scale)
- **Historical data is not a guarantee of future results** – the market and longevity statistics behind the Data-Grounded Exceptions are long-run historical averages; actual future returns or lifespans for any individual can and will differ

## Limitations

RiskAI is a **demonstration and research-oriented project**, and its outputs should be read accordingly:

- **Not financial advice** – wealth and net-worth projections are illustrative, not investment recommendations, even where they use real historical market statistics
- **Not medical advice** – Healthcare domain results do not constitute clinical or public-health guidance
- **Not legal advice** – no output should be relied on for compliance or legal decisions
- **Mostly directionally reasoned, not empirically validated** – this applies to 57 of 60 risk categories. The 3 Data-Grounded Exceptions (see Methodology) are the current exceptions to that statement, each grounded in real historical data or peer-reviewed methodology — but even those are general-population statistics and published models, not predictions calibrated to any specific individual or company
- **Decision support, not decision-making** – outputs are a starting point for discussion and further analysis, not a substitute for professional judgment

## Future Improvements

Planned or plausible directions for the modeling layer:

- **Extend Monte Carlo simulation to more domains** – currently limited to Stocks/ETF and Retirement wealth projections; Real Estate's wealth projection remains a single deterministic path
- **Machine learning models** – replacing or supplementing rule-based formulas with models trained on real outcome data, where such data becomes available
- **Bayesian networks** – explicit modeling of dependencies between risk categories, beyond the current correlation heuristics
- **Real-time economic / market data** – calibrating domain parameters (e.g., interest rates, regional real estate indices) against live external sources, rather than the fixed historical averages currently used
- **API integrations** – connecting to authoritative third-party data providers per domain
- **Custom risk models** – allowing organizations to supply their own weighting or formulas per domain
- **Closing the remaining Altman Z-Score proxy** – the Retained Earnings ratio is still approximated via book equity; a dedicated input or integration could resolve this

None of these are implemented today except where already described above. This section describes direction, not a roadmap with committed timelines.
